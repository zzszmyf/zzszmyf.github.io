把四套方案的年账单并排放在一起，差距比功能清单大得多：国内静态方案一年 ¥400-800，国内全栈 ¥4000-12000，Cloudflare 全栈约 ¥70，混合部署 ¥500-2000。这个差距主要来自固定的服务器和数据库月费，功能数量的影响反而小。对个人博客，先搞清楚哪一笔钱是为“可能到来的流量”预付的，再谈技术栈。

## 四套方案的账单结构

国内静态方案是阿里云或腾讯云域名 ¥100/年，OSS/COS 和 CDN 的月费在 ¥30-80 之间，年总成本按 ¥400-800 估。它解决的是国内访问速度和备案合规，适合客户都在国内、站点以展示为主的情况；代价是 CDN 按流量计费，流量突增时账单跟着涨，而且要维护 bucket、回源、证书和缓存规则。

国内全栈方案在这上面加了 ECS/CVM（¥100-500/月）和 RDS/CDB（¥100-300/月），再加对象存储 ¥10-50/月、CDN ¥50-200/月，一年 ¥4000-12000。它的月固定成本在服务器和数据库，流量为零也照付；对应的能力是完全控制、备案合规和云厂商的技术支持。只有出现登录、支付、客户数据留存这类需求，这笔固定成本才有对应的业务价值。

Cloudflare 全栈的现金支出只有域名，$10/年，约 ¥70；Pages、Workers、D1、R2、CDN 都在免费额度内。优势在零运维和全球边缘分发，代价是国内访问没有境内节点保底、Workers 和 D1 的能力边界比传统服务器窄。混合部署是前端放 Cloudflare Pages 或 Vercel，后端放阿里云函数计算/腾讯云 SCF，数据库用 PlanetScale 或 Supabase，一年 ¥500-2000；它想同时照顾两边用户的访问体验，代价是两套部署、两套监控和 DNS 分流。

## 国内静态方案

这套方案用 OSS/COS 加 CDN，不需要买服务器。静态文件上传到 bucket，绑定自定义域名，开 CDN 加速，证书用云厂商的免费证书；备案是前置条件，域名、接入商和备案主体要一致。它的优点是攻击面小、没有运行时、扩容由 CDN 承担；缺点是配置项多，缓存规则配错时，更新文章后用户可能几天看到旧页面，刷新 CDN 缓存要成为发布流程的一部分。

它适合国内企业客户为主的展示型博客。客户打开速度是获客的一部分，备案和国内节点能把首屏 RTT 压下来；如果站点只有文字和少量图片，OSS + CDN 的月账单通常落在前面说的 ¥30-80 区间。图片多、下载多、或者被转载时，按流量计费会变成主要成本，预算告警和流量封顶要提前设。

## 国内全栈方案

需要用户系统、CMS、CRM 或支付时，才轮到 ECS + RDS。ECS 给应用和后台任务，RDS 给关系数据，对象存储放附件，CDN 放静态资源；这套结构的优点是每一层都能独立扩容和备份，缺点是每一层都要人管。RDS 不是装完就完事：慢查询、连接数、备份保留期、主从延迟都要看；ECS 也不是买完就安全：安全组、系统补丁、日志和监控都要配。

这套方案适合业务已经稳定、客户数据必须落在境内、或者有合规要求的情况。它的成本固定，流量多少都要付；所以触发条件应该具体到“必须登录才能用的功能已经上线”或“客户要求数据存放在境内”；“感觉业务变大了”不算条件。在没有这些条件之前，这笔固定支出会先于收入出现。

## Cloudflare 全栈

Cloudflare 全栈把域名、DNS、静态托管、边缘函数、数据库和对象存储放在一个账号里。Pages 托管 VitePress 的构建产物，Workers 处理表单和轻量 API，D1 存关系数据，R2 放文件和备份，KV 放配置和缓存。免费额度覆盖个人博客绰绰有余，Pages 和 CDN 不单独计费，R2 免费 10GB，边缘函数和数据库的配额足够跑一个轻量咨询站。

限制也要提前知道。D1 是 SQLite，写入集中在一个主库，适合低频写入和简单查询，不适合高并发写或复杂事务；KV 是最终一致的，不能拿来做库存扣减；Workers 没有常驻进程和本地磁盘，长任务要拆成异步流程；未备案域名在国内可能走海外节点。把这些边界接受下来，这套方案是个人博客和轻量咨询站的最省心起点；要跑订单、支付或实时协作，应该直接看 Supabase、PlanetScale 或 VPS。

## 混合部署

混合部署的动机通常有两个：国内用户要求低延迟，海外用户也不能慢；或者后端必须放在境内，前端想保留 Cloudflare 的分发能力。做法是前端 Pages/Vercel，后端阿里云函数计算/腾讯云 SCF，数据库 PlanetScale/Supabase，Cloudflare DNS 按地区解析到不同前端。它能把两边都照顾到，但引入了两个发布流程、两套日志、两套证书和一条 GeoDNS 规则；任何一边挂掉，排查都要跨两个控制台。

这套方案适合已经有明确的双边用户、且有技术能力维护两套基础设施的团队。对刚开始写博客的人，它是过度设计：你会在配置 DNS 分流和跨云鉴权上花掉的时间，远多于它省下的那点延迟。混合部署的年成本看起来不高，但加上排障和迁移的人力，账就不一样了。

## 每一层怎么选

域名层，Cloudflare Registrar 的 .com 是 $9.77/年，续费同价；Namecheap 首年 $10.28、续费约 $14，隐私免费；Porkbun $10.37 续费同价，极简不推销；阿里云 .com 约 ¥70/年，隐私 ¥30/年，优势是备案和国内管理。纯静态博客选前三家都行；国内客户为主、要备案，直接选阿里云，省掉把域名转回境内的麻烦。

静态托管层，Cloudflare Pages 免费且不限带宽，Vercel 免费版给 100GB 流量/月，阿里云 OSS 约 ¥10-30/月，GitHub Pages 免费但国内较慢。一篇文章按 200KB、一天 1 万 PV 算，一个月约 60GB，文字博客的流量用不满免费额度；图片和下载多的站要按流量另算，Vercel 的 100GB 更适合纯文字站，图片站要么压图，要么选不限带宽的 Pages，要么接受国内 CDN 的账单。

Serverless 层，Workers 免费 10 万次/天，跑在 V8 isolate 上，适合轻量 API；Vercel Functions 免费 100GB-小时/月，和 Next.js 集成最好，但函数在海外 region 执行，国内访问慢；阿里云函数计算免费 100 万次/月，适合国内合规和低延迟。选哪家，先看你的前端在哪、用户在哪，再看免费额度。

数据库层，D1 是 SQLite，免费 5GB，适合边缘轻量数据；PlanetScale 是 MySQL，免费 5GB，有分支和 schema 变更流程；Supabase 是 Postgres，免费 500MB，自带 Auth、Storage 和 Realtime；阿里云 RDS 没有免费档，但合规、备份和技术支持最完整。关系数据优先 Postgres/MySQL，边缘配置和缓存用 KV，文件放对象存储；不要把文件塞进数据库，也不要用 KV 做需要事务的计数。

## 什么时候加钱

阶段一用 Cloudflare 全栈：域名 $10/年，Pages 托管 VitePress，Formspree 收表单，Giscus 做评论，只付域名钱。阶段二在咨询量起来后加 Workers、D1 和 Resend，把线索存下来，成本大约 ¥100/年；如果不想写代码，Airtable + Zapier 也能过渡。阶段三才切混合部署：前端 Vercel/Pages，后端函数计算或 Railway，数据库 PlanetScale/Supabase，支付 Stripe/支付宝，年成本 ¥2000-5000。

真正需要提前想清楚的，是数据放在哪、谁备份、出故障谁处理。技术栈可以从 ¥70/年起步，但一旦加上登录和支付，托管费只是小头，后面还有合规、备份和故障响应的责任。这条线跨过去之前，静态方案加第三方服务足够用；跨过去之后，再便宜的方案也不该省掉备份。
