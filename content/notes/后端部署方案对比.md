静态博客最容易被后端绑架的地方是评论、表单、订阅、搜索和统计。这五样都有成熟的前端或第三方方案：评论用 Giscus，表单用 Formspree，订阅用 Buttondown，搜索用 Pagefind，统计用 Plausible 或 umami。真正需要自己写服务端的场景没有想象中多，先把“伪需求”剔掉，再谈选型。

## 评论、表单、订阅、搜索和统计

评论系统里，Giscus 把评论存进 GitHub Discussions，登录用 GitHub OAuth，博客侧只嵌一段脚本，不需要数据库。Disqus 更省事，但会加载第三方脚本和广告，隐私上要接受它的数据策略。Twikoo 比 Giscus 灵活，支持邮件提醒和微信通知，代价是要部署一个函数实例并准备 MongoDB，运维面比纯静态多一层。

表单用 Formspree 或 Getform，免费档大约 500 次提交/月，POST 到它们的 endpoint，转发到你的邮箱；腾讯问卷适合国内用户，但样式和域名不是自己的。邮件订阅用 Mailchimp、ConvertKit 或 Buttondown，免费额度按订阅人数算，真正的成本在送达率和退订合规，不在服务器。搜索用 Algolia DocSearch 或 Pagefind：DocSearch 对文档站免费，但要申请；Pagefind 在构建时把 HTML 切成静态索引，浏览器直接查，没有 API 和数据库。统计用 Google Analytics、Plausible 或 umami，前者的代价是 cookie 同意和脚本体积，后两者可以自建，但自建就多了一个要备份的数据库。

这些方案的共同点是：数据不在你手里，或者只在你构建产物里。评论在 GitHub，表单在 Formspree，订阅在邮件服务商，搜索索引在静态文件里，统计在第三方。对个人博客，这是合理的取舍；如果客户数据、合规或数据主权是硬要求，下面的后端方案才有意义。

## 什么时候真的需要后端

需要自己写服务端的信号很具体：内容要登录才能看，且用户能自助注册、找回密码；非程序员要通过 CMS 改内容；销售要在一个后台里跟踪咨询线索；要收钱，且涉及订单、退款、webhook 回调；要做实时聊天或协作；要把咨询业务产品化成 SaaS。这些功能的共同点是有状态、有权限、有写入，且状态不能只存在浏览器里。

登录这个功能，界面上只有一个注册按钮，背后却是密码哈希、邮箱验证、会话或 token 过期、找回密码、账号禁用和审计日志；支付表面上是一次 API 调用，背后是 webhook 验签、幂等键、对账和退款状态机；实时功能要维持长连接，Serverless 函数的生命周期通常不适合常驻 WebSocket。把这些机制列出来，就能判断某个需求该不该现在做：如果现在说不清谁负责备份、谁处理账号申诉，先别上后端。

## Serverless：Cloudflare、Vercel、Supabase

Cloudflare 的全栈是 Pages + Workers + D1 + R2 + KV。Workers 免费档 10 万次请求/天，超出 $0.50/百万次；D1 是 SQLite，免费 5GB，写入集中在一个主库，适合低频写入和轻量关系数据，不适合高并发写或复杂事务；R2 兼容 S3，免费 10GB，出网不单独计费；KV 是最终一致的键值存储，适合配置和缓存，不适合计数器和库存。Workers 跑在 V8 isolate 里，冷启动比容器型函数轻，真正的延迟大头通常是 D1 查询、跨境回源和第三方 API。它适合“表单提交、简单认证、少量读”的场景；把它当主数据库跑订单系统，会在事务边界和写入吞吐上撞墙。

Vercel 的全栈是 Next.js + Functions + 托管数据库。免费档给 100GB-小时/月的函数用量，支持 Node.js、Python、Go；函数跑在你配置的 region，Vercel 没有中国大陆节点，所以国内访问慢的不只是静态资源，函数请求的 RTT 也受影响。它的优势是 Next.js 的本地开发到部署路径顺，ISR、图片优化、预览环境都集成好了；代价是流量和函数用量增长后账单上升快，数据库还要另选 PlanetScale、Supabase 或 Vercel Postgres。

Supabase 是 Postgres 全家桶：免费 500MB 数据库、2GB 存储，Pro $25/月，自带 Auth、Storage、Realtime 和自动生成 API。它的核心是 Postgres 和 Row Level Security，权限写在数据库策略里，前端可以直接查；代价是免费项目闲置会被暂停，Serverless 函数直连 Postgres 容易打满连接数，要用连接池。它适合需要完整后端、又不想自己写认证和 CRUD 的产品；如果只是博客加一个表单，Supabase 的运维面比 Formspree 大得多。

## VPS 和 PaaS

VPS 的价格很清楚：Vultr、Linode 的 1C1G 是 $5/月，DigitalOcean 是 $6/月，Hetzner 的 2C4G 是 €4.5/月，阿里云 ECS 和腾讯云 CVM 的 1C1G 大约 ¥60/月。它的代价不在月费，而在你成了系统管理员：安全更新、备份、监控、TLS 续期、日志轮转、fail2ban 都要自己配；单机还是单点故障，扩容要自己加机器，高可用得自己配。1C1G 的机器同时跑 Postgres、应用和构建，内存会先于 CPU 成为瓶颈，一次 OOM 或磁盘写满就够排查半天；这件事能做，但要把运维时间算进成本。

PaaS 介于两者之间：Railway $5/月起，Render 有免费档、付费从 $7/月起，Fly.io 按量付费且在香港有节点，Heroku $7/月起。它替你处理部署、SSL、负载均衡和部分扩缩容，代价是控制权少、迁移时要重写构建配置，免费档还会休眠，下一次请求要等实例起来。对没有专职运维的小团队，PaaS 通常比 VPS 更划算；对需要特定内核参数、GPU 或常驻后台任务的服务，VPS 或容器平台更合适。

## 按阶段加，不要一次到位

博客起步阶段用纯静态：VitePress 构建，Cloudflare Pages 或 Vercel 托管，Formspree 收表单，Giscus 做评论，年成本约 ¥70。这个阶段不要买数据库，也不要先写用户系统；没有真实写入，数据库只会增加备份和连接配置的负担。

咨询业务增长后，如果每月咨询量超过 50 条、需要跟踪线索，再上轻量 Serverless：Workers 处理表单 API，D1 存线索，Resend 或 SendGrid 发邮件，或者先用 Airtable（免费 1200 行）+ Zapier 过渡。Airtable 方案的好处是不写后端，30 分钟能跑通；坏处是数据在第三方、复杂查询和权限控制弱。这个阶段仍然只需要付域名的钱，其余在免费额度里。

产品化阶段才需要完整后端：Next.js + Prisma，数据库用 PlanetScale（MySQL）或 Supabase（Postgres），部署用 Vercel 或 Railway，支付接 Stripe，成本大约 $20-50/月（¥150-350）。再往后是 Docker + Kubernetes、阿里云/腾讯云，月成本 ¥1000+，这时才需要谈高可用和合规。升级的触发条件很具体：出现了必须登录、必须收钱、必须留存客户数据的业务动作。

## 上登录之前先回答三个问题

上后端最先要付的成本是备份、权限和故障处理，服务器月费排在后面。上登录之前，先回答三个问题：数据存在哪里、谁每天备份、账号丢失时怎么恢复。答不上来，前面那套第三方组合的成本和运维面都远低于自建后端；答得上来，再选 Workers、Supabase 或 VPS 都不迟。
